# OpenCode Architecture Overview

> **Purpose:** This document provides a comprehensive overview of the OpenCode architecture, including the main components, data flow, and platform-specific implementations.

---

## 1.1 System Overview

OpenCode is an AI-powered coding agent built with TypeScript and designed to work across multiple platforms (Linux, macOS, Windows, FreeBSD). It uses a client-server architecture with a terminal-based TUI frontend.

### 1.1.1 Key Characteristics

- **Multi-platform support:** Linux (x64, arm64, musl), macOS, Windows, FreeBSD
- **Client-server architecture:** Allows remote control of the agent
- **Extensible plugin system:** Supports MCP (Model Context Protocol) servers
- **Cross-runtime compatibility:** Works with Bun and Node.js runtimes

## 1.3 Core Components

### 1.3.1 CLI Entry Point (`src/index.ts`)

The main entry point handles:
- Command-line argument parsing (yargs)
- Global initialization (logging, environment)
- Command routing (run, generate, serve, etc.)

### 1.3.2 Agent (`src/agent/`)

The agent is the core AI component that:
- Processes user messages
- Executes code changes via tools
- Maintains conversation context
- Handles multi-step reasoning

Key file: `agent.ts`

### 1.3.3 Session Management (`src/session/`)

Manages the conversation lifecycle:
- `session.ts` — Session state and persistence
- `message.ts` — Message handling
- `message-v2.ts` — Enhanced message processing
- `prompt.ts` — Prompt construction
- `compaction.ts` — Context compaction for long conversations
- `llm.ts` — LLM API interactions

### 1.3.4 Server (`src/server/`)

HTTP and WebSocket server implementation:
- `server.ts` — Main server logic
- `adapter.bun.ts` / `adapter.node.ts` — Platform-specific adapters
- `proxy.ts` — Proxy functionality
- `workspace.ts` — Workspace management
- `middleware.ts` — Request/response middleware

### 1.3.5 PTY Management (`src/pty/`)

Pseudo-terminal handling:
- `pty.bun.ts` — Bun-specific implementation (uses `bun-pty`)
- `pty.node.ts` — Node.js implementation (uses `node-pty`)
- `index.ts` — Common PTY interface

### 1.3.6 Storage (`src/storage/`)

Database and persistence:
- `db.ts` — Main database interface
- `db.bun.ts` / `db.node.ts` — Platform-specific database initialization
- `json-migration.ts` — JSON migration utilities
- `schema.sql.ts` — Database schema definitions

## 1.4 Platform-Specific Implementations

### 1.4.1 Conditional Imports

OpenCode uses Node.js conditional imports for platform-specific code:

```typescript
// packages/opencode/package.json
{
  "imports": {
    "#pty": {
      "bun": "./src/pty/pty.bun.ts",
      "node": "./src/pty/pty.node.ts",
      "freebsd": "./src/pty/pty.node.ts",
      "default": "./src/pty/pty.bun.ts"
    },
    "#hono": {
      "bun": "./src/server/adapter.bun.ts",
      "node": "./src/server/adapter.node.ts",
      "freebsd": "./src/server/adapter.node.ts",
      "default": "./src/server/adapter.bun.ts"
    },
    "#db": {
      "bun": "./src/storage/db.bun.ts",
      "node": "./src/storage/db.node.ts",
      "freebsd": "./src/storage/db.node.ts",
      "default": "./src/storage/db.bun.ts"
    }
  }
}
```

### 1.4.2 PTY Implementations

| Platform | Implementation | Library |
|----------|---------------|---------|
| Bun/Linux | `pty.bun.ts` | `bun-pty` |
| Node.js/Linux | `pty.node.ts` | `@lydell/node-pty` |
| FreeBSD | `pty.node.ts` | `@lydell/node-pty` |
| macOS | `pty.node.ts` | `@lydell/node-pty` |
| Windows | `pty.node.ts` | `@lydell/node-pty` |

### 1.4.3 Server Adapters

| Platform | Implementation | Library |
|----------|---------------|---------|
| Bun | `adapter.bun.ts` | `Bun.serve()` |
| Node.js | `adapter.node.ts` | `@hono/node-server` |

### 1.4.4 Database Adapters

| Platform | Implementation | Library |
|----------|---------------|---------|
| Bun | `db.bun.ts` | `bun:sqlite` |
| Node.js | `db.node.ts` | `node:sqlite` + `drizzle-orm` |

## 1.5 Build System

### 1.5.1 Build Targets

The build script (`script/build.ts`) produces binaries for:

| OS | Architectures | Notes |
|----|--------------|-------|
| Linux | x64, arm64, x64-baseline, x64-musl, arm64-musl | glibc default, musl available |
| Darwin | x64, arm64, x64-baseline | macOS |
| Windows | x64, arm64, x64-baseline | |
| FreeBSD | x64, arm64 | **In development** |

### 1.5.2 Build Configuration

Key configuration in `script/build.ts`:

```typescript
const allTargets: {
  os: string
  arch: "arm64" | "x64"
  abi?: "musl"
  avx2?: false
}[] = [
  // ... Linux, Darwin, Windows targets ...
  {
    os: "freebsd",
    arch: "x64",
  },
  {
    os: "freebsd",
    arch: "arm64",
  },
]
```

### 1.5.3 BunFS Root Path

Platform-specific paths for the bunfs virtual filesystem:

| Platform | Path |
|----------|------|
| Windows | `B:/~BUN/root/` |
| FreeBSD | `/usr/local/lib/opencode/` |
| Others | `/$bunfs/root/` |

## 1.6 Data Flow

### 1.6.1 CLI Command Flow

```
User Input (CLI args)
    ↓
index.ts (yargs)
    ↓
Command Handler (cmd/run.ts, etc.)
    ↓
Agent Initialization
    ↓
Session Management
    ↓
LLM Interaction
    ↓
Tool Execution
    ↓
Result/Response
```

### 1.6.2 Server Request Flow

```
HTTP/WebSocket Request
    ↓
Server Adapter (bun/node)
    ↓
Middleware Chain
    ↓
Route Handler
    ↓
Service Logic
    ↓
Database/Storage
    ↓
Response
```

### 1.6.3 Agent Session Flow

```
User Message
    ↓
Message Processing
    ↓
Prompt Construction
    ↓
LLM API Call
    ↓
Response Parsing
    ↓
Tool Execution
    ↓
Context Update
    ↓
Response to User
```

## 1.7 Configuration System

### 1.7.1 Config Modules

Located in `src/config/`:

| File | Purpose |
|------|---------|
| `config.ts` | Main configuration logic |
| `agent.ts` | Agent-specific settings |
| `provider.ts` | AI provider configuration |
| `mcp.ts` | MCP server settings |
| `plugin.ts` | Plugin configuration |
| `permission.ts` | Permission settings |
| `lsp.ts` | LSP server settings |
| `keybinds.ts` | Keybinding configuration |

### 1.7.2 Config Pattern

Config modules follow a self-export pattern:

```typescript
// src/config/agent.ts

  // ...
}

// src/config/config.ts

```

## 1.10 Security Considerations

### 1.10.1 Permission System

OpenCode implements a permission system in `src/permission/`:
- File system access control
- Command execution restrictions

### 1.10.2 Plugin Security

MCP plugins run in isolated contexts with:
- Permission checks before tool calls
- Resource access control
- Sandboxed execution
